# PrismPress 产品原则与验收边界

2026-11-17 用户重申，后续设计和实现必须遵守。

## 产品初心

帮助不同用户减少一稿多发的实际操作，尽可能在 PrismPress 内完成排版、图片处理、摘要标签、封面及发布准备。功能是否成立，按整条任务的操作成本和结果判断，而非页面按钮数量。

## 不可把核心工作退回给用户

- 默认流程不得要求用户逐图下载、重新上传、替换链接或反复修复排版；这些只能是异常恢复手段，不能作为主方案。
- 普通用户无需自备 PicList、图床、Cloudflare 或开发者密钥。已有 PicList 集成保留为高级选项。
- 图片处理应由产品承担：获取、必要的格式处理、缓存、上传或转存、链接替换、失败重试和逐图结果反馈。
- 本地预览成功、域名分类为公开、复制成功，都不等于目标平台已接收图片或保存草稿。不得显示未经验证的完成状态或“七端通杀”等保证。

## 减少操作与账号权限

- 网站不能在完全无授权的情况下操作任意用户的公众号图片库或草稿箱。
- 官方接口路线需核对账号接口权限；产品化时优先由运营方完成第三方接入，让用户通过明确的账号授权连接，而非默认要求用户填写 AppID/AppSecret。
- 浏览器发布助手是候选路线：用户首次安装、授予必要权限并登录目标平台；之后从 PrismPress 发起图片处理及草稿交付。尚未实现或验证，不得宣称已支持。
- 账号授权或安装确有必要时，应明确说明一次性操作及用途，不得承诺“零配置全自动”。
- 保留无需绑定账号的排版与预览入口；该入口的交付能力必须如实描述，不能冒充自动上传与保存草稿。

## 早期确认的公众号图片流程（2026-11-17）

用户已在公众号编辑器检查到一次粘贴后的图片地址变为微信 `mmbiz.qpic.cn`，并决定优先完善无需 Cloudflare 的本地图片复制路线。

- Markdown 编辑区保留短图片路径；配图单独保存于当前浏览器。
- 生成预览和剪贴板正文时关联图片数据，让公众号粘贴时有机会自行接收并转存。
- 不要求普通用户配置或登录 Cloudflare；PicList 是可选高级能力。
- 旧草稿中已有的 Base64 图片应迁移到图片存储，不能为缩短原稿而丢弃图片。
- 更换同路径的图片后，原复制记录必须失效；刷新后需恢复原稿和配图。
- 本地剪贴板验证只能证明图片数据已写入，不能代替公众号实际保存、重新打开及手机预览检查。

暂缓官方接口及浏览器发布助手的开发；其他平台逐一验证，不将微信单次成功推断为全部平台、全部账号可靠。

## 当前交付流程（2026-11-23）

- 默认使用“预览→准备发布→复制并打开平台→用户粘贴检查发布”，不依赖安装助手，不设体验口令；服务端密钥由运营方配置。
- 顶部与原稿区共用导入入口，支持正文文件或文章文件夹。多篇正文先选择一篇，只有图片时明确说明未更换正文，不用含糊成功提示让用户误判。
- B站、抖音文章使用图片数据复制；其他正文平台的本地配图使用站内托管。图片准备失败不得静默漏图，等待必须有进度、取消与超时出口。
- 默认查看“AI 工程五级进阶”示例；个人草稿主动恢复，查看示例不覆盖草稿。小红书只提供当前图集路线，抖音保留文章与图集。
- 2026-11-23用户反馈已逐个平台体验、暂未发现问题并授权部署。此为用户确认，不能冒称助手独立验收所有平台、所有格式。
